## Update 59 - Ask SOULEY understands the question (Nov 15)

Before, the page needed the right tab and answered every question the same way ("Here are published destinations that best match your request"). Now the server reads the question first.
SERVER: services/intent.js (pure: language en/fil/ceb, town and area, activity, budget, days, pace, group, month, difficulty, what is asked, place named, "it / the second one" follow-ups), services/answerWriter.js (pure: all reply text in 3 languages), services/aiService.js (new ask() in front of the old flow; `recommend(prefs, { auto: true })`). Both /api/ai/recommendations and /api/ai/itinerary now call it. Request has an optional `ctx` ({ q, ids[], days }) = the chat so far. Response adds `chips` (what was understood), `suggestions` (next questions), `intent` (places | trip | facts | compare | nearby | chat), `lang`, `engine: 'smart'`.
BEHAVIOUR: a question that asks for a trip becomes a trip even on the Recommendations tab (days read from the question; a value sent by the form still wins). Town in the question = filter; no match for the activity there = says so and looks elsewhere. "Where can I eat" = food only. Facts about a named place are always answered from the record (never by the AI, so never invented); missing data says "not listed yet" and quotes the place's own description where it mentions fees, hours or how to get there. Greetings, thanks, "who are you", other places (Bohol...) get a short reply without a search. With AI_API_KEY the model still writes recommendation text, now with the understood request in the prompt and told to answer in the visitor's language.
DATA GUARDS (important): (1) the spot model fills entranceFee "Free" and difficulty "easy" for every place nobody edited; when 90%+ of places say that it is treated as a default and shown as "not listed yet". Fill real fees in the admin and the answers start using them. (2) Many places share one pin (the town centre); a pin shared by 3+ places is treated as approximate: no distance, "directions" becomes a name search on Google Maps, "what is near X" falls back to the same town.
CLIENT: pages/Ask.jsx sends `ctx` with a typed follow-up (not with the first question, not with the fixed follow-up chips); components/ask/Reply.jsx shows a "What I picked up" chip row and "You can also ask" buttons (these replace the fixed follow-up chips when the server sends them), and says "Answered from our spot database." instead of "AI model not connected" for smart answers.
